Open **Connected apps** from the sidebar, choose a service, and complete its authorization in your normal browser. OpenMausBot turns the resulting connection into tools that supported agent engines can use.

## Add your Composio project key

Connected apps run through your own [Composio](https://composio.dev) project. There is no built-in or managed connection, so nothing connects until you add that project's key:

1. In the [Composio Dashboard](https://dashboard.composio.dev), select or create a project and open **Settings → API Keys**.
2. Copy a project key beginning with `ak_`.
3. In OpenMausBot, open **App Settings → Connections** and save it under **Composio project key**.
4. Open **Connected apps**, search for Gmail, GitHub, Slack, Notion or another toolkit, and select **Connect**.
5. Finish OAuth in the browser window that opens, then return to the app and ask a bot to use the service.

The desktop app keeps the key in Electron's operating-system-backed secure storage. Provider OAuth tokens remain with Composio and are not written into bot prompts or the renderer. A source or headless build can use `COMPOSIO_API_KEY` instead; see [Self-hosted Composio](./self-hosted-composio.mdx).

## Connect X (Twitter)

To let bots **search and read** X, you do not need an X account or a Composio connection. Open **Apps** and find the **X (Twitter)** card, and paste your own [treg](https://treg.to) key (it is the same key as under **Settings → API keys**). The card checks it with treg and shows your balance or the exact problem. **Test** checks it again, and **Remove key** takes it away. Calls are billed to your treg balance.

Every bot then gets **Research (treg)**: read-only tools to search posts, read an account's posts, read a post with its replies and look up a profile, plus research tools that find and call treg's catalog for companies, people, funding, news and more. Without a key, no bot is shown these tools. Turn them off for one bot in its settings under **Access**. A routine on that bot can check X on a schedule and report only new posts.

The steps below are only needed to **post** to X through Composio. Composio does not provide managed credentials for its `twitter` toolkit. To connect an X account:

1. Create an app in the X Developer Portal.
2. Create a `twitter` auth config in your Composio project using that app's credentials.
3. Save the project's key under **App Settings → Connections**.
4. Return to **Connected apps** and connect **X (Twitter)**.

Older OpenMausBot tasks that refer to the connector as `x` continue to work; OpenMausBot translates that alias to Composio's `twitter` toolkit automatically.

## Apps that need your own OAuth app

Some apps, such as Xero and Buffer, have no sign-in that Composio provides, so they connect only with your own OAuth app:

1. In your Composio project, create an auth config for the app (**Auth Configs → Create**) with your OAuth app's client ID and secret, and keep it enabled.
2. Save the project's key under **App Settings → Connections**.
3. Connect the app from **Connected apps**, or let a bot ask for it in chat.

OpenMausBot finds the auth config by itself, switches on what Composio needs before it uses it ("enabled for Tool Router", which a config you made yourself can have off), and tells the bot which config it used. If you have several for one app, it uses the most recently created. A connection you made in the Composio dashboard itself is not visible to OpenMausBot, so connect the app once from OpenMausBot.

## Multiple accounts

Connect more than one account for the same toolkit and give each a clear alias such as `work`, `personal`, or `client-acme`. When several accounts could perform an action, OpenMausBot requires explicit selection instead of silently replacing the first connection.

## Limit which tools a bot may use

Connecting a service makes its tools available to the workspace; it does not hand every bot every tool. Open a bot's settings on the desktop and, under **Connected apps**, choose per service whether that bot gets **all tools**, an **exact list** of tools, or **no tools**.

By default every bot keeps all tools on the apps it can see — nothing changes when you upgrade or connect a new app until you assign a grant. Once a bot has any grant, services missing from its list grant it nothing. Imported bots and shareable packages always land with no grants.

Phones show each bot's grants read-only in its profile under **App tools**. Editing happens on the computer; a paired phone can never change grants.

## Disconnecting

Disconnecting an account revokes the upstream grant. It does not only hide the account in the local UI. Other accounts for the same toolkit remain connected.
